# БЭНГ! — веб-версия настольной игры

Браузерная версия карточной игры **«Бэнг!»** (Bang!) — перестрелка в стиле спагетти-вестерна для 4–7 игроков.
Играют на **одном устройстве** («hot seat»): игроки по очереди садятся за экран, а игра скрывает чужие карты, пока экран передают следующему.

Правила реализованы по официальному русскому изданию — файл [`bang-rules.pdf`](bang-rules.pdf) в корне проекта (версия правил 1.1, «Мир Хобби»).
Если код и PDF расходятся, прав PDF.

## Быстрый старт

Нужен **Node.js 20.19+ или 22.12+** (этого требует Vite 8) и npm.

```bash
npm install      # установить зависимости
npm run dev      # запустить в режиме разработки → http://localhost:5173
```

Нажмите **«Играть»** на главной (или откройте `/game`), выберите число игроков, введите имена и нажмите «Раздать карты».

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер разработки с горячей перезагрузкой |
| `npm run build` | Проверка типов (`tsc -b`) и сборка в папку `dist/` |
| `npm run preview` | Запуск собранной версии из `dist/` |
| `npm run lint` | Проверка кода ESLint |
| `npm test` | Тесты правил игры (Vitest) |

Перед тем как отправлять изменения, должны проходить три команды: `npm run lint`, `npm run build`, `npm test`.

## Коротко о правилах игры

Этого достаточно, чтобы читать код. Подробности — в [`bang-rules.pdf`](bang-rules.pdf).

**Роли.** Каждый игрок получает тайную роль. Шериф раскрывает свою сразу.

| Роль | Цель |
|---|---|
| Шериф | Убить всех бандитов и ренегата |
| Помощник | Помогать шерифу (побеждает вместе с ним) |
| Бандит | Убить шерифа |
| Ренегат | Остаться последним выжившим |

Сколько каких ролей — зависит от числа игроков (4–7), см. `src/game/data/roles.ts`.

**Персонажи.** Каждому достаётся один из 16 персонажей. У персонажа есть **здоровье** (3 или 4, шериф получает +1) и **особое свойство** — например, «может сыграть сколько угодно „Бэнг!" за ход».

**Ход** состоит из этапов:

1. **Проверки** — если перед игроком лежат «Динамит» или «Тюрьма», сначала вскрывается карта колоды (см. «Проверка» ниже).
2. **Набор** — взять 2 карты из колоды.
3. **Розыгрыш** — сыграть сколько угодно карт, но не больше одного «Бэнг!» за ход.
4. **Сброс** — на руке может остаться не больше карт, чем у игрока здоровья.

**Карты** бывают двух видов:
- **коричневые** (разовые) — сыграл, применил эффект, карта ушла в сброс («Бэнг!», «Мимо!», «Отдых»…);
- **синие** (постоянные) — кладутся перед игроком и действуют, пока лежат («Бочка», «Мустанг», оружие…).

**Расстояние** между игроками — сколько мест между ними по кратчайшей стороне стола. «Бэнг!» можно сыграть только в игрока на расстоянии не больше дальности вашего оружия (без оружия — 1).

**Проверка** — вскрыть верхнюю карту колоды и посмотреть её масть. Например, «Бочка» отменяет попадание, если вскрыта черва ♥.

**Гибель.** Потеряв последнее здоровье, игрок может сразу сыграть «Отдых» и выжить. Иначе он выбывает и открывает роль.

**Конец игры** — когда убит шериф (побеждают бандиты или ренегат) или убиты все бандиты и ренегат (побеждает закон).

## Архитектура: как всё связано

Главная идея — **правила игры отделены от интерфейса**.

```
┌──────────────────────────┐   действие    ┌─────────────────────┐   действие   ┌──────────────────────┐
│  React-компоненты        │  ───────────▶ │  useGameStore       │ ───────────▶ │  src/game            │
│  (кнопки, карты, стол)   │               │  (Zustand)          │              │  gameReducer(s, a)   │
│                          │ ◀───────────  │  хранит GameState   │ ◀─────────── │  → новое состояние   │
└──────────────────────────┘ новое состояние└─────────────────────┘ новое состояние└──────────────────────┘
          │                                                                             ▲
          │       «можно ли сыграть эту карту?», «кто может быть целью?»                │
          └─────────────────────────────────────────────────────────────────────────────┘
                          прямой вызов функций из src/game/rules
```

1. **`src/game`** — чистый TypeScript. Не знает про React, браузер и экран. Его можно запустить в тестах, на сервере, в консоли.
2. **`src/store/useGameStore.ts`** — тонкая прослойка. Хранит текущее состояние партии и передаёт действия в движок. Правил тут нет.
3. **React-компоненты** только показывают состояние и отправляют действия. Чтобы подсветить, какую карту можно сыграть, они спрашивают у движка (`canPlayCard`, `getValidTargets`) — **те же функции**, которыми движок проверяет действия. Поэтому правило никогда не расходится между «что подсвечено» и «что сработает».

### Почему так

- **Легко проверять правила.** Тест — это «вот состояние, вот действие, проверь результат». Ни браузера, ни React не нужно.
- **Легко найти механику.** Хочешь понять, как работает «Динамит», — открываешь `src/game/mechanics/turn.ts`.
- **Можно сделать сетевую игру.** Тот же движок можно запустить на сервере — интерфейс менять почти не придётся.

## Игровой движок изнутри

### Главная функция

```ts
import { createGame, gameReducer } from './game';

let state = createGame(['Аня', 'Боря', 'Вика', 'Гоша']);   // новая партия
state = gameReducer(state, { type: 'DRAW_CARDS' });          // шериф берёт карты
state = gameReducer(state, { type: 'PLAY_CARD', cardId: 'bang-3', targetId: 'player-2' });
```

`gameReducer` — **чистая функция**: получает старое состояние и действие, возвращает новое. Старое состояние не изменяется (везде используется копирование `{ ...state }`). Если действие недопустимо (не твой ход, карту нельзя сыграть), возвращается **то же самое** состояние — ничего не происходит.

### Состояние партии (`GameState`)

Всё, что нужно знать о партии, лежит в одном объекте (`src/game/types.ts`):

| Поле | Что хранит |
|---|---|
| `players` | Игроки **в порядке рассадки по часовой стрелке**: роль, персонаж, здоровье, рука (`hand`), карты в игре (`inPlay`) |
| `activePlayerId` | Чей сейчас ход |
| `phase` | Этап хода: `TURN_START` → `DRAW` → `PLAY` → `DISCARD`, в конце — `GAME_OVER` |
| `deck` / `discard` | Колода и сброс. **Верхняя карта — последний элемент массива** |
| `bangsPlayedThisTurn` | Сколько «Бэнг!» уже сыграно (лимит — 1) |
| `prompt` | Чего игра ждёт прямо сейчас и **от кого** (см. ниже) |
| `queue` | Очередь будущих запросов |
| `generalStore` | Открытые карты «Магазина» |
| `winner` | Кто победил (`LAW`, `OUTLAWS`, `RENEGADE`) или `null` |
| `log` | Журнал событий для игроков |

### Запросы (`prompt`) — ключевая идея

Иногда игра должна дождаться решения **другого** игрока, не того, чей ход. Например, игрок А стреляет в Б — теперь Б решает: сыграть «Мимо!», проверить «Бочку» или потерять здоровье.

Такое ожидание описывается **запросом** (`Prompt`). У каждого запроса есть:
- `kind` — тип: `RESPOND_TO_SHOT` (ответить на выстрел), `DYING` (спастись от гибели), `GENERAL_STORE_PICK` (выбрать карту в магазине) и т. д.;
- `actorId` — **кто** должен принять решение.

Отсюда простое правило: **действовать может только «текущий игрок»** — `prompt.actorId`, а если запроса нет — активный игрок. Его возвращает функция `getActorId(state)`.

### Очередь (`queue`) и «досчёт» (`settle`)

Некоторые карты затрагивают нескольких игроков по очереди: «Гатлинг» стреляет во всех, в «Магазине» каждый выбирает карту. Для этого запросы кладутся в **очередь**.

После **каждого** действия движок вызывает `settle` (`src/game/engine.ts`), который «доводит партию до следующего решения»:

```
1. Срабатывает Сюзи Лафайет (если у неё пустая рука — тянет карту).
2. Есть победитель или открытый запрос? → стоп, ждём игрока.
3. Активный игрок погиб в свой ход?      → ход переходит дальше.
4. В очереди есть запрос?                → открыть его (выбывших пропустить).
5. Проверки начала хода закончились?     → перейти к набору карт.
```

Благодаря этому карты вроде «Гатлинга» не управляют очерёдностью сами: они просто кладут запросы в очередь, а `settle` выдаёт их по одному.

### Слои движка

| Папка | Что в ней | Пример |
|---|---|---|
| `data/` | Неизменные справочники | Состав колоды: 25 «Бэнг!», 12 «Мимо!»… |
| `core/` | Элементарные операции над состоянием | «Взять верхнюю карту колоды», «убрать карту с руки» |
| `rules/` | Вопросы «можно ли?» — ничего не меняют | «Какое расстояние от А до Б?», «Можно ли сыграть эту карту?» |
| `mechanics/` | Механики хода | Передача хода, проверка «Тюрьмы», потеря здоровья, выбывание |
| `cards/` | Эффекты конкретных карт | «Дуэль», «Магазин», «Паника!» |

Зависимости идут сверху вниз: `cards → mechanics → rules → core → data`. Нижние слои ничего не знают о верхних.

**Полная таблица «правило → файл»** — в [`src/game/README.md`](src/game/README.md).

### Случайность

Все перемешивания идут через `src/game/core/random.ts`. В тестах источник случайности можно подменить (`setRandomSource`), чтобы результат был предсказуемым.

## Пример: что происходит, когда игрок стреляет

Разберём по шагам, как «Бэнг!» проходит через весь код.

**1. Игрок кликает карту «Бэнг!» на руке** (`src/features/controls/Hand.tsx`).
Компонент спрашивает движок: `canPlayCard(game, playerId, card)` → `true`, и `needsTarget(player, card)` → `true` (нужна цель). Карта переходит в режим выбора цели: `setTargeting(card.id)`.

**2. Игроки, в которых можно попасть, подсвечиваются красным** (`src/entities/player/PlayerStation.tsx`).
Список целей даёт `getValidTargets` (`src/game/rules/playability.ts`), а он использует расстояние из `src/game/rules/distance.ts`.

**3. Игрок кликает по цели** → `dispatch({ type: 'PLAY_CARD', cardId, targetId })`.

**4. Хранилище** (`src/store/useGameStore.ts`) вызывает `gameReducer(game, action)`.

**5. Движок** (`src/game/cards/playCard.ts`):
- ещё раз проверяет, что карту можно сыграть (защита от ошибок интерфейса);
- убирает карту с руки, кладёт её в сброс, увеличивает `bangsPlayedThisTurn`;
- вызывает `shootBang` (`src/game/cards/shooting.ts`), который создаёт запрос `RESPOND_TO_SHOT` с `actorId` = цель.

**6. Интерфейс видит, что `actorId` сменился** — значит, за экран должен сесть другой игрок. Показывается заставка «Передайте экран» (`PassDeviceOverlay`), руки скрыты.

**7. Цель нажимает «Я — …» и отвечает.** Варианты:
- сыграть «Мимо!» с руки → запрос закрыт, попадание отменено;
- «Проверить „Бочку"» → `defendWithCheck` вскрывает карту; черва ♥ — попадание отменено;
- «Потерять здоровье» → `dealDamage` (`src/game/mechanics/health.ts`) отнимает 1 здоровье.

**8. Если здоровье упало до 0**, `dealDamage` смотрит, есть ли чем спастись. Есть «Отдых» — открывается запрос `DYING`. Нет — `eliminatePlayer` (`mechanics/elimination.ts`): роль раскрывается, карты уходят в сброс, начисляются награды и штрафы, проверяется победа.

**9. `settle`** видит, что запроса больше нет, и возвращает ход стрелявшему игроку.

### Как работает «hot seat»

В хранилище есть поле `seatedPlayerId` — кто подтвердил, что сейчас сидит за экраном. Если игра ждёт решения от другого игрока (`getActorId(game) !== seatedPlayerId`), рука и кнопки скрываются и показывается заставка «Передайте экран». Игрок нажимает «Я — …» → `takeSeat()` → заставка исчезает.

Стол масштабируется под размер окна (`src/shared/hooks/useFitScale.ts`), а страница игры не прокручивается.

|---|---|
| `setup.test.ts` | Состав колоды, роли для 4–7 игроков, раздача |
| `distance.test.ts` | Расстояние, «Мустанг», «Прицел», оружие, «Паника!» |
| `shooting.test.ts` | «Бэнг!», «Мимо!», лимит за ход, «Бочка», «Гатлинг», «Индейцы!», «Дуэль» |
| `turn.test.ts` | Набор, сброс, передача хода, «Динамит», «Тюрьма», персонажи в фазе набора |
| `death.test.ts` | Гибель и «Отдых», награды и штрафы, условия победы, «Магазин» |

Тест строится так: собрать нужное состояние (`makeGame`), применить действия (`run`), проверить результат.

```ts
it('«Мимо!» отменяет попадание', () => {
  const bang = card('BANG');
  const missed = card('MISSED');
  const game = run(
    makeGame([{ hand: [bang] }, { hand: [missed] }, {}, {}]),   // 4 игрока: у p1 «Бэнг!», у p2 «Мимо!»
    { type: 'PLAY_CARD', cardId: bang.id, targetId: 'p2' },      // p1 стреляет в p2
    { type: 'PLAY_CARD', cardId: missed.id },                    // p2 отвечает «Мимо!»
  );
  expect(player(game, 'p2').hp).toBe(4);                          // здоровье не изменилось
});
```

Помощники `card`, `makeGame`, `run`, `player` — в `src/game/__tests__/helpers.ts`. В колоде (`deck`) верхняя карта — **последняя** в массиве: это важно, когда тест проверяет «Бочку» или «Динамит».

**Если меняете правила — сначала напишите тест**, который описывает правильное поведение по PDF.

## Как добавить новую карту или персонажа

### Новая карта

1. **`src/game/types.ts`** — добавить вид карты в `CardKind`, например `'WHISKY'`.
2. **`src/game/data/cards.ts`** — название и текст в `CARD_DEFINITIONS`, масти и достоинства в `DECK_COMPOSITION`.
3. **`src/shared/cardArt.ts`** — значок карты. TypeScript сам напомнит: без этого проект не соберётся.
4. **Эффект:**
   - разовая карта без цели → функция в `src/game/cards/` и строка в `OWN_TURN_EFFECTS` (`src/game/cards/playCard.ts`);
   - карта с целью → ещё и в `needsTarget` / `getValidTargets` (`src/game/rules/playability.ts`);
   - синяя карта → действует там, где её проверяют (например, `hasInPlay(player, 'WHISKY')`).
5. **Тест** в `src/game/__tests__/`.

### Новый персонаж

1. **`src/game/types.ts`** — идентификатор в `CharacterId`.
2. **`src/game/data/characters.ts`** — имя, здоровье, описание.
3. **Картинка** — `public/images/rules/character-<id>.svg`.
4. **Свойство** — в том месте движка, где оно срабатывает. Ориентир — список в начале `src/game/rules/characterRules.ts`:
   влияет на расстояние → `rules/distance.ts`; на набор → `mechanics/drawPhase.ts`; на потерю здоровья → `mechanics/health.ts` и т. д.
5. **Тест.**

## Соглашения в коде

- **Названия — как в правилах.** Карты и персонажи называются точно так, как в `bang-rules.pdf` («Отдых», а не «Пиво»; «Мимо!», а не «Промах!»). Внутренние идентификаторы — английские оригинальные имена (`slab_the_killer` = Ангельские Глазки), русское имя подписано рядом.
- **Комментарии ссылаются на правила:** «(стр. 9)» — страница PDF, откуда взято правило.
- **Движок не мутирует данные.** Любое изменение — новый объект: `{ ...state, phase: 'PLAY' }`.
- **Одно правило — одно место.** Проверка «можно ли» живёт в `rules/`, и ею пользуются и движок, и интерфейс. Не дублируйте условия в компонентах.
- **Движок не импортирует React** и ничего из `src/features`, `src/entities`, `src/pages`. Интерфейс берёт из движка всё через `src/game/index.ts`.
- **Комментарии и тексты — на русском**, имена переменных и функций — на английском.
- **Стили** — классы Tailwind прямо в разметке. Цвета темы (`bang-red`, `bang-brown`, `bang-plate`…) заданы в `src/index.css`.

## Что пока не сделано

- **Только игра на одном устройстве.** Сетевой игры и игроков-ботов нет. Движок к этому готов: его можно запустить на сервере без изменений.
- **История и профиль** показывают моковые данные (`src/shared/data/mockGameHistory.ts`) — сохранения партий нет.
- **Партия не сохраняется** при перезагрузке страницы.
- **Картинки персонажей** (`public/images/rules/character-*.svg`) содержат старые имена, нарисованные прямо в изображении (например, «Сид Кетчум» вместо «Том Кетчум»). В подсказках, журнале и итогах партии используются правильные имена из правил.
- **Упрощённый вариант** правил (без карт с символом книги) не поддерживается.
- На **невысоких экранах** (около 650 px) рука частично перекрывает место игрока слева внизу.
